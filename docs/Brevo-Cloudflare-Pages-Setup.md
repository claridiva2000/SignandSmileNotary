# Connect Brevo to a Cloudflare Pages Contact Form

This guide documents the working setup for sending a Cloudflare Pages contact form through Brevo using an authenticated business domain.

## Architecture

- The website submits the form to a Cloudflare Pages Function, such as `POST /api/contact`.
- The Pages Function calls Brevo's transactional email API.
- Brevo sends the inquiry from a domain-based sender address.
- Cloudflare Email Routing forwards incoming mail for the business address to an existing inbox.
- The Brevo API key remains encrypted and is never included in the browser bundle or Git repository.

## Values used in this example

Replace these values for another website:

| Purpose | Value |
| --- | --- |
| Business domain | `signandsmiletexas.com` |
| Sender address | `hello@signandsmiletexas.com` |
| Destination inbox | `signandsmilenotary@gmail.com` |
| API key binding | `BREVO_API_KEY` |
| Sender binding | `CONTACT_FROM_EMAIL` |

## 1. Create an incoming email route

Cloudflare Email Routing makes the domain address capable of receiving messages without requiring a separate paid mailbox.

1. In Cloudflare, go to **Compute > Email Service > Email Routing**.
2. Select **Onboard Domain** and choose the business domain.
3. Approve the MX, SPF, and DKIM records Cloudflare proposes.
4. Under **Destination Addresses**, add the inbox that should receive forwarded mail.
5. Open the verification email sent to that inbox and approve it.
6. Return to **Email Routing > Routing Rules**.
7. Create a rule for the local part of the business address. For example:
   - Email pattern: `hello`
   - Domain: `signandsmiletexas.com`
   - Action: **Send to an email**
   - Destination: `signandsmilenotary@gmail.com`
8. Save the rule and confirm that it is active.
9. Test the route by emailing the business address from a different account.

> Avoid testing from the same inbox that receives the forwarded message. Some providers may discard mail that appears to loop back to its sender.

## 2. Authenticate the domain in Brevo

Free sender domains such as Gmail, Yahoo, and Outlook should not be used as the Brevo sender. Authenticate a domain the business owns.

1. In Brevo, go to **Settings > Senders, Domains & Dedicated IPs > Domains**.
2. Select **Add a domain** or **Set up a domain**.
3. Enter the business domain.
4. Choose manual authentication if you want to review every DNS change yourself.
5. Brevo will provide domain-specific DNS records, normally including:
   - A Brevo verification TXT record
   - One TXT DKIM record or two CNAME DKIM records
   - A DMARC TXT record
6. Keep the Brevo page open while adding the records in Cloudflare.

Always use the exact record names and values generated by the Brevo account. Do not reuse example DKIM values from another domain.

## 3. Add Brevo's DNS records in Cloudflare

1. In Cloudflare, select the domain and go to **DNS > Records**.
2. For every record displayed by Brevo, select **Add record**.
3. Copy Brevo's record type, name, and value into Cloudflare.

### DNS field mapping

| Brevo field | Cloudflare field |
| --- | --- |
| Type | Type |
| Name | Name |
| Content | Content for TXT records or Target for CNAME records |

For CNAME DKIM records:

- Brevo **Content** goes in Cloudflare **Target**.
- Use **DNS only**, not proxied.
- Leave TTL set to **Auto**.
- Do not add `https://`, quotation marks, or spaces.

### DMARC warning

Search existing DNS records for `_dmarc` before adding the record. A domain should have only one DMARC record. If one already exists, update or merge it carefully instead of creating a duplicate.

A starter DMARC policy may look like this, but use the value Brevo requests for the domain:

```text
v=DMARC1; p=none; rua=mailto:rua@dmarc.brevo.com
```

## 4. Verify the domain in Brevo

1. Return to the domain page in Brevo.
2. Select **Authenticate domain**, **Verify**, or **Check configuration**.
3. Confirm that domain ownership, DKIM, and DMARC have green status indicators.

DNS updates often appear within minutes but can take longer to propagate. If verification does not pass immediately, wait and retry before changing valid-looking records.

## 5. Create the Brevo sender

1. In Brevo, go to **Settings > Senders, Domains & Dedicated IPs > Senders**.
2. Select **Add a sender**.
3. Enter the business name as the From name.
4. Enter the domain-based address as the From email.
5. Save the sender.

When the complete domain is authenticated, Brevo may not require separate verification for each sender. If it sends a verification message, Cloudflare Email Routing should forward it to the destination inbox.

## 6. Create the Brevo API key

1. In Brevo, go to **Settings > SMTP & API > API Keys & MCP**.
2. Select the API Keys section.
3. Generate a new API key.
4. Give it an identifiable name, such as `Business Contact Form - Cloudflare`.
5. Copy the key immediately.

Use an **API key**, not an SMTP key, when the Pages Function calls Brevo's HTTP API.

Never place the API key in source code, `wrangler.toml`, client-side environment variables, screenshots, chat messages, or Git.

## 7. Store the API key in Cloudflare

1. In Cloudflare, open **Workers & Pages** and select the Pages project.
2. Go to **Settings > Variables and Secrets**.
3. Add the following production secret:

| Type | Name | Value |
| --- | --- | --- |
| Secret | `BREVO_API_KEY` | The Brevo API key |

4. Ensure encryption is enabled.
5. Add the same secret to Preview only if preview deployments need to send real emails.

The Pages Function should access the key through the runtime environment, for example:

```js
const apiKey = context.env.BREVO_API_KEY;
```

## 8. Configure the sender variable

If the project uses `wrangler.toml` as its configuration source, add the non-sensitive sender address under `[vars]`:

```toml
[vars]
CONTACT_FROM_EMAIL = "hello@signandsmiletexas.com"
```

Do not put `BREVO_API_KEY` in this file.

The Pages Function should read the sender value at runtime:

```js
const fromEmail = context.env.CONTACT_FROM_EMAIL;
```

If the repository has both `wrangler.toml` and `wrangler.json` or `wrangler.jsonc`, determine which file Cloudflare is actually using. Avoid maintaining conflicting Wrangler configurations.

## 9. Commit, push, and deploy

Saving `wrangler.toml` locally is not enough. Commit and push it:

```bash
git status
git add wrangler.toml
git commit -m "Add contact email environment variable"
git push origin main
```

Wait for Cloudflare's automatic production deployment to finish.

Do not rely solely on a deployment's timestamp. A manual retry may rebuild the same old commit. Confirm that the new deployment displays a different commit hash containing the configuration change.

## 10. Verify the deployed variables

1. Open the new production deployment in Cloudflare.
2. Expand the collapsed **Build settings** section in **Deployment details**.
3. Confirm that both values are listed:
   - `BREVO_API_KEY` — encrypted
   - `CONTACT_FROM_EMAIL` — the domain sender address
4. Confirm that the custom domain aliases point to the new production deployment.

This deployment-details check is important: a variable may appear in project settings but still be absent from a particular deployment.

## 11. Test the contact form

1. Open Cloudflare's real-time Functions logs.
2. Submit one request through the live contact form.
3. Confirm that the website displays success.
4. Confirm that the inquiry reaches the destination inbox.
5. Select Reply and confirm that it addresses the customer's submitted email.
6. Check Spam and Promotions if the message does not appear in the primary inbox.

A success message on the website is not sufficient proof. Confirm that the email actually arrived.

## Troubleshooting

### The endpoint returns HTTP 500

Open Cloudflare's real-time logs and inspect the newest `POST /api/contact` event. Server-side `console.log` and `console.error` output appears in Cloudflare logs, not the browser's developer console.

If the log says:

```text
Contact function misconfigured: BREVO_API_KEY or CONTACT_FROM_EMAIL is not set.
```

one or both runtime bindings are missing from that deployment. Check the expanded Build settings, update the configuration, and create a new deployment.

### Cloudflare says the invocation outcome is `ok`, but the browser receives 500

`outcome: ok` means the Function executed without an uncaught platform exception. The Function can still intentionally return HTTP 500 after detecting a configuration problem or receiving an error from Brevo.

### The website reports success, but no email arrives

Check for an early-return path such as a honeypot. A browser password manager or autofill feature can populate a poorly configured hidden field, causing the server to treat a legitimate request as spam and return a silent success without calling Brevo.

During initial integration testing, log only privacy-safe milestones such as:

- Function entry
- Whether each required binding exists, as Booleans
- Whether the Brevo request was attempted
- Brevo's HTTP status
- Whether a message ID was returned
- The final status returned to the browser

Never log API keys or customer form contents.

### The new deployment is recent but does not contain the change

Compare commit hashes. If the recent deployment has the same hash as an older deployment, Cloudflare rebuilt the old source. Commit and push the local change, then verify that the resulting deployment has a new hash.

### Brevo rejects the sender

Confirm that:

- The From address uses the authenticated business domain.
- The domain has passing DKIM and DMARC status in Brevo.
- The sender exists in Brevo.
- The Brevo account's transactional email service is active.
- The API key is valid and has not expired or been deactivated.

## Security checklist

- Keep the Brevo API key in an encrypted Cloudflare secret.
- Never expose the API key to browser code.
- Never commit secrets to Git.
- Validate contact-form fields on the server.
- Escape customer-provided values before inserting them into HTML email.
- Use the customer's email as Reply-To, not From.
- Avoid logging personally identifiable form data.
- Return generic errors to website visitors while retaining useful, privacy-safe server logs.
- Add or restore spam protection after the basic email pipeline has been proven end to end.
